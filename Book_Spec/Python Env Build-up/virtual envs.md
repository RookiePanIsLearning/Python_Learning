Python 建立虛擬環境的方式非常多樣，從 Python 內建的標準工具到功能強大的第三方套件管理系統都有。依照複雜度與使用情境，主要可以分為以下 **6 種主流方式**：

### 1. `venv` (Python 內建標準)

這是目前最基本、也最常用的方式。從 Python 3.3 開始成為標準函式庫的一部分，**不需要額外安裝**就能使用。

- **優點**：開箱即用、非常輕量。
- **缺點**：功能單一，只負責建立環境，套件相依性管理仍需仰賴 `pip` 和 `requirements.txt`。
- **適用情境**：新手入門、簡單的腳本、不需要複雜相依性管理的專案。
- **建立指令**：`python -m venv myenv`

### 2. `virtualenv` (老牌且強大的第三方工具)

在 `venv` 成為標準之前，它是建立虛擬環境的絕對主流。雖然現在基本功能被 `venv` 取代，但它依然有其優勢。

- **優點**：建立環境的速度比 `venv` 快，且支援舊版 Python (如 Python 2)。
- **缺點**：需要額外使用 `pip install virtualenv` 來安裝。
- **適用情境**：需要頻繁建立環境，或需要維護舊版 Python 專案時。
- **建立指令**：`virtualenv myenv`

### 3. `Conda` (資料科學與機器學習首選)

Conda 是 Anaconda 和 Miniconda 附帶的環境與套件管理員。它不僅能管理 Python 套件，還能處理 C/C++ 等底層語言的相依性。

- **優點**：跨語言支援、解決複雜的底層依賴問題（例如自動搞定 NumPy 或 TensorFlow 需要的 C 函式庫），且可以**自由指定 Python 版本**。
- **缺點**：環境佔用空間較大、解析套件衝突時有時會比較慢。
- **適用情境**：資料科學、資料分析、機器學習等需要大量非 Python 底層函式庫的領域。
- **建立指令**：`conda create --name myenv python=3.10`

### 4. `Pipenv` (結合 Pip 與 Virtualenv)

Pipenv 的目標是將 npm (Node.js) 或 yarn 的開發體驗帶入 Python。它會自動為專案建立和管理虛擬環境，並在安裝/解除安裝套件時自動更新 `Pipfile` 和 `Pipfile.lock`。

- **優點**：自動管理虛擬環境與套件、提供 `lock` 檔案確保不同機器上的環境完全一致。
- **缺點**：套件解析有時較慢，社群活躍度近年來略有下降。
- **適用情境**：一般的應用程式開發（如 Web 開發）。
- **建立指令**：`pipenv install` (會自動建立環境)

### 5. `Poetry` (現代化的專案與相依性管理)

Poetry 是近年來非常受歡迎的現代化工具，它使用單一的 `pyproject.toml` 檔案來管理套件相依性、專案設定甚至是打包發佈。

- **優點**：極佳的相依性解析演算法、標準化的設定檔格式、內建打包發佈功能。
- **缺點**：學習曲線比純 `venv` 高一點。
- **適用情境**：中大型專案、需要發佈套件到 PyPI 的開發者、重視相依性安全性的團隊。
- **建立指令**：`poetry env use python` 或直接 `poetry install`。

### 6. `uv` (新世代的極速工具)

由 Astral (開發 ruff 的團隊) 使用 Rust 語言全新打造的 Python 套件與環境管理工具。

- **優點**：**速度極快**（比 pip/virtualenv 快數十倍）、可以直接取代 pip、venv 和 pip-tools。
- **缺點**：相對較新，但社群接受度與成長速度驚人。
- **適用情境**：追求極致安裝速度與效能的開發者。
- **建立指令**：`uv venv`
